# 멤버십 프로모션 운영 규칙

## 기본 원칙

멤버십 프로모션은 백엔드가 이벤트 대상, 기간, 가격, 노출 조건을 관리하고, 프론트는 이벤트 타입별 화면 템플릿을 관리하는 구조를 기본 원칙으로 한다.

백엔드가 화면 전체를 CMS처럼 제어하는 서버 드리븐 UI 방식은 앱 품질 관리 비용이 크므로 기본 선택지로 두지 않는다. Flutter 앱은 앱 버전 차이, 배포 지연, 심사, 레이아웃 QA, 문구 길이, 디자인 시스템 준수 문제가 있기 때문에 DB 변경만으로 완전히 새로운 이벤트 화면이나 UX를 노출하는 구조는 지양한다.

## 책임 경계

### 백엔드/DB에서 관리하는 항목

- 이벤트 활성 여부
- 시작/종료 시각
- 현재 유저가 이벤트 대상인지 여부
- 가격 및 상품 id
- 우선순위
- 제목, 부제목, 배지, CTA 같은 짧은 문구
- 약관 및 유의사항 문구
- 이미지 URL

### 프론트에서 관리하는 항목

- 화면 구조
- 컴포넌트 배치
- 결제 플로우
- 가격 표시 방식의 세부 UI
- 이벤트 타입별 UX
- 디자인 시스템 적용
- 앱 버전별 fallback

## 프로모션 타입 기반 렌더링

프로모션은 `type + template` 패턴으로 확장한다. 백엔드는 현재 유저에게 적용 가능한 프로모션 설정을 내려주고, 프론트는 `type`에 따라 이미 앱에 구현된 화면 템플릿을 선택한다.

예를 들어 `FIRST_PURCHASE_DISCOUNT` 타입은 첫 멤버십 구매 유저 특가를 의미한다. 해당 타입의 레이아웃과 결제 UX는 프론트에 배포되어 있어야 하며, 백엔드는 기간, 대상 조건, 가격, 문구, 이미지 같은 운영 값을 제공한다.

## 대상 판정 원칙

프론트가 이벤트 기간과 대상 여부를 직접 조합해서 최종 적용 여부를 판단하지 않는다. 백엔드는 현재 유저에게 적용 가능한 프로모션을 최종 판정하여 내려준다.

프론트는 `activePromotion`이 있으면 프로모션 화면을 렌더링하고, 없으면 기본 멤버십 화면을 렌더링한다. 가격, 결제, 혜택은 보안과 정합성이 중요하므로 프론트의 자체 판단에 의존하지 않는다.

## 변경 가능 범위

DB 또는 어드민 조작만으로 변경해도 되는 범위는 같은 프로모션 타입 안에서의 문구, 가격, 기간, 대상, 우선순위 조정이다.

완전히 새로운 화면 구조, 컴포넌트 배치, 결제 흐름, 강조 방식, UX가 필요한 이벤트는 새 프로모션 타입과 프론트 배포를 통해 추가한다.

## 첫 구매 특가 프로모션

첫 멤버십 구매 유저 특가는 별도 프로모션 타입으로 정의한다.

- 타입: `FIRST_PURCHASE_DISCOUNT`
- 대상: 유료 멤버십 결제 이력이 없는 유저
- 노출: 백엔드가 현재 유저에게 적용 가능하다고 판정한 경우
- 가격: 첫 결제 주문에만 적용되는 할인 price로 제공
- fallback: 적용 가능한 프로모션이 없거나 앱이 해당 타입을 지원하지 않으면 기본 멤버십 화면 노출

## 첫 달 할인 적용 원칙

첫 달 할인은 정가 멤버십 상품을 복제한 별도 할인 상품으로 관리하지 않고, 첫 결제 시점에만 적용되는 가격 정책으로 관리한다.

- 멤버십 상품은 정가 기준으로 관리한다.
- 구독 계약은 정가 멤버십 상품을 기준으로 생성한다.
- 첫 결제 주문에만 프로모션 가격을 적용한다.
- 다음 갱신부터는 정가 기준으로 결제한다.
- 프로모션 적용 사실과 당시 가격은 결제 이력으로 보존한다.

이 구조를 사용하면 첫 달에는 할인 금액으로 결제하고, 다음 갱신부터는 동일한 멤버십 상품의 정가 기준으로 결제할 수 있다.

### 주문 생성 검증

구독 주문 생성 시 서버는 클라이언트가 전달한 금액을 신뢰하지 않는다.

1. 요청된 정가 멤버십 상품을 확인한다.
2. 현재 유저에게 적용 가능한 첫 달 할인 정책이 있는지 확인한다.
3. 유저에게 유료 멤버십 결제 이력이 없는지 확인한다.
4. 할인 대상이면 프로모션 가격을 기대 결제 금액으로 사용한다.
5. 할인 대상이 아니면 정가를 기대 결제 금액으로 사용한다.
6. 클라이언트가 전달한 결제 금액과 서버가 계산한 기대 결제 금액이 다르면 주문 생성을 거부한다.

유료 멤버십 결제 이력은 구독 보유 여부만으로 판단하지 않는다. 어드민 부여, 파트너십, 무료 멤버십이 섞일 수 있으므로 실제 유료 결제 이력을 기준으로 판단한다.

기본 기준은 다음과 같다.

- 구독 주문이다.
- 결제 상태가 완료 상태다.
- 실제 결제 금액이 0원보다 크다.

환불된 첫 결제도 프로모션 재사용 방지를 위해 유료 결제 시도 이력으로 본다.

### 프로모션 적용 이력

첫 달 할인 적용 이력은 구독 계약이 아니라 첫 결제 주문의 이력으로 남긴다. 프로모션은 구독 기간 전체에 적용되는 혜택이 아니라 첫 결제 1회에 적용된 가격 정책이기 때문이다.

이력에는 최소한 다음 정보가 남아야 한다.

- 어떤 주문에 적용되었는지
- 어떤 프로모션이 적용되었는지
- 정가가 얼마였는지
- 실제 첫 결제 금액이 얼마였는지
- 언제 적용되었는지

예를 들어 베이직 첫 달 할인은 다음 의미로 보존한다.

- 구매한 멤버십 상품: 베이직
- 정가: 9900원
- 첫 결제 금액: 5900원
- 구독 갱신 기준 금액: 베이직 정가

### 환불 정책

첫 달 할인 주문의 환불 기준 금액은 멤버십 정가가 아니라 실제 결제 금액을 사용한다.

예를 들어 베이직 정가가 9900원이고 첫 달 할인 결제 금액이 5900원이면 환불 가능 최대 금액은 5900원이다.

프로모션 적용 이력은 환불 후에도 삭제하지 않는다. 과거 주문에 어떤 프로모션 가격이 적용되었는지 추적하기 위해 이력으로 보존한다.

### iOS 결제 정책

iOS 자동 갱신 구독은 App Store Connect의 introductory offer를 사용한다.

- 정가 구독 상품에 첫 달 할인 offer를 설정한다.
- 첫 달에는 Apple transaction의 실제 결제 금액을 주문 결제 금액으로 저장한다.
- 구독 계약은 정가 구독 상품을 기준으로 생성한다.
- offer 기간이 종료되면 Apple 정책에 따라 정가로 자동 갱신된다.

서버는 Apple transaction의 결제 금액과 offer 정보를 주문 및 프로모션 이력에 저장할 수 있어야 한다.
