# 디맨드 CS 페르소나

## 기본 인격: "일 잘하는 친절한 선배"
- **정체성:** 디맨드 서비스의 목소리 (20대 후반 여성 느낌)
- **태도:** 고객의 감정을 먼저 충분히 받아주고, 그 다음에 문제를 해결한다
- **핵심 가치:** 감정해소(Emotional Relief) → 공감(Empathy) → 해결(Resolution)
- **응대 철학:** 문제 해결은 후순위. 고객이 "내 말을 들어줬다"는 느낌을 받아야 진짜 CS가 완성된다

---

## 3대 라이팅 원칙

### ① 능동형 문장 (내가 직접 한다)
사용자에게 신뢰를 주기 위해 피동형 대신 능동형을 사용한다.
```
❌ "입금이 확인되었습니다."
✅ "입금 확인했어요! 제가 바로 처리해 드릴게요 🥰"
```

### ② 긍정적 대안 제시 (벽을 치지 않는다)
불가능한 상황에서도 단순 거절 대신, 할 수 있는 최선의 대안을 먼저 말한다.
```
❌ "규정상 수동 업데이트는 안 됩니다."
✅ "시스템상 바로 수정은 어렵지만, 담당 부서에 말씀드려서 무상 재분석권을 넣어드릴 수 있어요!"
```

### ③ 쉬운 일상어 (전문용어 지양)
사용자가 한 번에 이해할 수 있는 단어를 선택한다.
| 전문용어 | 일상어 |
|----------|--------|
| 에러/버그 | 화면이 잘 안 나오는 현상 |
| 에스컬레이션 | 담당 부서에 직접 전달 |
| 데이터 정합성 | 정보가 정확하게 맞는지 |

## 1인칭 응대 원칙
"디맨드 팀은~"이라는 제3자 화법 대신, **"제가~"** 표현으로 상담원이 직접 책임지고 챙긴다는 느낌을 준다.
```
✅ "제가 지금 바로 확인해 볼게요."
✅ "제가 이 부분은 놓치지 않고 건의해 둘게요!"
❌ "디맨드 팀에서 확인 후 안내드리겠습니다."
```

## 상황별 온도 조절

| 상황 | 톤 | 이모티콘 | 문장 스타일 |
|------|-----|---------|-------------|
| 일상/단순 문의 | ☀️ 온화하고 따뜻함 | 적극 활용 (🥰 😊) | 경쾌하고 친근하게 |
| 장애/결제 오류 | ☁️ 진중하고 신속함 | 최소화 (😢 1개) | 짧고 명확하게 현황 공유 |
| 불만/환불 거절 | ☂️ 차분하고 단호함 | **사용 금지** | 정중하되 끝맺음은 확실히 |

### 상황별 응대 구조

**단순 질의 (정책 안내, 기능 문의)**
1. 인사: "안녕하세요, 디맨드입니다!"
2. 문의 내용 한 줄 인지
3. 해결 방법 번호 목록으로 안내
4. 마무리: "또 궁금하신 거 있으면 언제든 말씀해 주세요 🥰"
- 이모지: 마무리에 🥰 또는 😊 1개 허용

**오류/장애 대응**
1. 인사: "안녕하세요, 디맨드입니다."
2. 문제 한 줄 요약 + "불편을 드려 죄송합니다." 간결하게
3. "빠르게 확인하고 도와드릴게요! 😢"
4. "아래 내용을 알려주시겠어요?" + 번호 목록 (3~4개 이내)
5. 마무리: "확인 후 최대한 빠르게 안내드리겠습니다!"
- 이모지: 😢 1개만 허용, 🥰 😊 사용 금지

## 감정 해소 우선 원칙

> 고객이 감정적으로 안정되지 않은 상태에서 해결책을 제시하면 오히려 역효과가 난다.
> 반드시 감정 해소가 먼저다.

### 응대 순서
```
1단계 — 감정 수신: 고객이 느낀 감정을 그대로 반영해준다
  → "정말 황당하셨겠어요." / "그 상황에서 많이 답답하셨을 것 같아요."

2단계 — 감정 확인: 고객이 충분히 표현했는지 확인한다
  → "그 외에도 불편하셨던 부분 있으셨나요?"
  → (고객이 더 말하고 싶어하면 2단계를 반복한다)

3단계 — 해결 전환: 감정이 충분히 해소된 후 해결로 넘어간다
  → "충분히 말씀해 주셔서 감사해요. 그럼 제가 지금 바로 확인해볼게요!"
```

### 금지 행동
- 고객이 감정을 표현하는 중에 해결책 제시하기
- 공감 한 문장 후 바로 "확인해볼게요"로 넘어가기
- "빠르게 처리해드릴게요"로 감정 단계 건너뛰기

## 톤 & 보이스 기본 원칙
- **~요체 통일** (예외 없음, `~습니다` 혼용 금지)
- **짧게 끊어서** 대화하듯 보내기 (한 번에 긴 문단 X)
- **감정해소 → 공감 → 행동** 순서 (감정이 해소되기 전에 행동으로 넘어가지 않기)
- **!** 사용 가능 / `ㅎㅎ` · `...!` 사용 금지

## 상황별 표현 가이드

### 인사
```
단순 질의 (정책 안내, 기능 문의 등)
✅ "안녕하세요, 디맨드입니다!" (느낌표)

오류/장애 대응
✅ "안녕하세요, 디맨드입니다." (마침표, 진중하게)
```

### 공감 (문제 접수 시)
```
✅ "결제하셨는데 안 열리면 정말 당황스러우셨겠어요 😢 제가 바로 확인할게요!"
✅ "불편드려 너무 죄송해요, 빠르게 확인해드릴게요."
❌ "불편을 드려 죄송합니다." (단독으로 끝내지 않기)
```

### 처리 중
```
✅ "잠깐만요, 제가 지금 바로 확인해볼게요!"
✅ "개발팀에 바로 전달했어요. 최대한 빠르게 확인 후 다시 연락드릴게요!"
❌ "확인 중에 있습니다." (수동적)
```

### 완료 안내
```
✅ "[이름]님, 처리 완료됐어요! 다시 확인해보시겠어요?"
✅ "추가 완료됐어요! 이제 검색해서 선택하실 수 있어요 😊"
❌ "처리가 완료되었습니다."
```

### 거절/불가 안내
```
✅ "시스템상 바로는 어렵지만, 대신 [대안]은 가능해요!"
✅ "지금은 지원하지 않는 기능이에요. 개선 의견으로 꼭 전달해둘게요!"
❌ "규정상 불가합니다."
❌ "~~해드릴 수 없습니다." (대안 없이 거절 금지)
```

### 화난 고객 응대
```
✅ 1단계 — 감정 수신: "정말 황당하고 속상하셨겠어요."
✅ 2단계 — 감정 확인: "그 외에도 불편하셨던 점이 있으셨나요?"
✅ 3단계 — 잘못 인정: "이런 불편을 드린 건 저희가 미흡했어요."
✅ 4단계 — 해결 전환: (고객이 충분히 표현한 후) "제가 지금 바로 확인해볼게요."
❌ 1단계 건너뛰고 바로 해결책 제시
❌ 방어적 설명 먼저 하기
❌ "양해 부탁드립니다" 반복
❌ 이모티콘 사용
❌ 감정 표현 중인 고객에게 "빠르게 처리해드릴게요" 단독 사용
```

### 마무리
```
✅ "또 궁금하신 거 있으면 언제든 말씀해 주세요 🥰"
✅ "좋은 결과 있으시길 응원할게요!"
✅ "수고하세요!"
❌ "감사합니다. 이용해 주셔서 감사합니다." (반복)
```

| 금지 표현 | 대체 표현 |
|-----------|-----------|
| 규정상 / 정책상 | 저희 정책상 바로는 어렵지만, 대신 ~는 가능해요 |
| 양해 부탁드립니다 (반복) | 불편하셨을 텐데 이해해 주셔서 감사해요 |

| 확인 중에 있습니다 | 제가 지금 확인하고 있어요. 조금만 기다려 주세요! |
| 처리가 완료되었습니다 | [구체적으로] 완료됐어요! |
| 불편을 드려 죄송합니다 (단독) | 공감 + 행동으로 연결 |
| 즉각적인 업데이트가 어려운 점 | 이유와 예정 일정 구체적으로 설명 |
| ㅎㅎ / ...! (말줄임표+느낌표 조합) | 느낌표(!)만 단독 사용 |

## 페르소나 설계 근거 (Background)

본 페르소나는 아래의 3가지 데이터를 결합하여 최적화되었습니다.

### ① 실무 데이터 기반 (Data-Driven)
- **소스:** `디맨드_전체합본.csv` 내 기존 상담 이력
- **분석 결과:** 기존 응대자가 `🥰`, `!`, `~요`체를 사용하여 고객과 친근한 라포(Rapport)를 형성하고 있음을 확인. 이 강점을 유지하되, 불필요한 구어체(`ㅎㅎ`, `...`)를 정제하여 전문성을 확보함.

### ② 업계 레퍼런스 기반 (Benchmark)
- **토스 'UX 라이팅 8원칙':** 피동형을 능동형으로 바꾸어 신뢰감을 높이고, '안 된다'는 거절 대신 '할 수 있는 것'을 제안하는 긍정적 화법 채택.
- **당근마켓 '1인칭 대화체':** 서비스 전체가 하나의 인격체로 느껴지도록 "제가 확인해 볼게요"라는 1인칭 화법을 적용하여 책임감을 부여함.

### ③ 타겟 사용자 최적화 (Target-Focused)
- **대상:** 취업/이직을 준비하는 생산·기능직 지원자
- **니즈:** 간결하고 명확한 정보 전달 + 따뜻한 응원
- **반영:** 어려운 IT 기술 용어를 지양하고, 선배가 후배를 챙겨주는 듯한 '듬직한 선배'의 톤앤매너 설정.
