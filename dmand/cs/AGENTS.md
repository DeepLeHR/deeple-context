## 스킬별 용도

### cs-router
**용도:** 문의 유형을 파악하여 적절한 전문 스킬로 위임하거나, 단순 FAQ는 직접 처리
**언제 사용:** CS 문의의 첫 진입점. 유형이 명확하지 않을 때
**라우팅 규칙:**
| 문의 유형 | 위임 대상 |
|-----------|-----------|
| 앱/웹 오류, 기능 불가, 결제 오류 | cs-bug-handler |
| 환불 요청 | cs-refund-check |
| 이메일 변경, 인증 해제, 탈퇴 | cs-account-manager |
| 기업명 검색 안됨, 자격증 수정 | cs-data-curator |
| 멘토 미연락, 멘토링 문의 | cs-mentoring-mediator |
| 가이드북, 멤버십 혜택 | 직접 처리 (FAQ) |

### cs-bug-handler
**용도:** 앱/웹 오류 제보 수집, 즉시 해결 vs 개발팀 에스컬레이션 판단
**처리 흐름:**
1. 셀프 해결 안내 (강력 새로고침, 앱 재시작)
2. 오류 정보 수집 (기기, 경로, 증상, 스크린샷)
3. 재현 가능 여부 판단
4. 즉시 처리 or 개발팀 전달 결정

**우선순위 기준:**
- 🔴 긴급: 결제 후 서비스 이용 불가 / 다수 동일 오류
- 🟡 일반: 기능 오류, 간헐적 현상
- 🟢 낮음: 단순 UI 문의

### cs-bug-analyze
**용도:** cs-bug-handler가 에스컬레이션 필요로 판단한 케이스를 받아 원인 가설 분류 + Jira 티켓 초안 생성
**처리 흐름:**
1. 수집된 유저 정보 확인 (기기, 경로, 증상 등)
2. 원인 유형 분류: A(클리언트/환경) / B(입력값/데이터) / C(API/서버) / D(UI/상태)
3. 우선순위 판단 (Critical/High/Medium/Low)
4. Jira 티켓 초안 출력

### cs-code-debug
**용도:** Jira 티켓 또는 버그 설명을 받아 실제 코드베이스에서 원인 파일·함수·라인을 특정 (개발팀 전용)
**특징:** `screen-code-db-map.md` 내장 매핑 테이블로 Glob 탐색 없이 파일 직접 조회

### cs-refund-check
**용도:** 환불 조건을 정책과 대조하여 승인/거절/보류를 판정하고 응답 문구 생성
**처리 흐름:**
1. 상품 유형 확인 (스펙리포트 / 멘토링 / 멤버십)
2. 열관 여부 또는 멘토 연락 여부 조회
3. 정책 대조 후 판정
4. 응답 문구 생성

### cs-account-manager
**용도:** 본인 확인 후 계정 직접 조작이 필요한 모든 요청 처리
**처리 가능:** 이메일 변경 / 기업 인증 해제 / 현직자 인증 승인 / 구독 해지 후 탈퇴 / 소셜 로그인 이슈

### cs-data-curator
**용도:** 이력서 기업명 DB 추가, 자격증명 수정 등 데이터 관련 요청 처리
**판단:** 일반 기업 → ✅ / 폐업 기업 → ❌ / 일반 매장 → ❌

### cs-mentoring-mediator
**용도:** 멘토 미연락 중재, 멘토-멘티 연결 확인, 환불 전환 판단
**처리:** 당일~1일(대기) → 2~3일(재요청) → 3일+(환불 전환)

## 권장 사용 흐름

```
[CS팀 흐름]
문의 인입
    ↓
문의 유형을 모름 → cs-router
문의 유형을 앎  → 해당 스킬 직접 실행
    ↓
응답 문구가 필요함  → cs-reply-draft
환불 심사가 필요함  → cs-refund-check
버그 에스컬레이션   → cs-bug-handler → cs-bug-analyze → Jira 티켓 초안

[개발팀 흐름]
Jira 버그 티켓 확인
    ↓
cs-code-debug → 원인 파일·라인 특정
```
